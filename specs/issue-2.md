# 스펙: 술 마신 사람만 술값 나눠 내기 (#2)

## 사용자 문제

회식 자리에 술을 마신 사람과 안 마신 사람이 함께 있다. 지금 계산기는 총액을 인원수로 똑같이 나누기 때문에, 술을 안 마신 사람도 술값을 같이 낸다. 사용자는 **술값은 마신 사람끼리만 나누고, 나머지(음식값 등)는 전원이 나누기**를 원한다.

## 제품 스펙

### 입력

기존 입력 두 개 아래에 두 개를 더한다.

| 입력 | 설명 | 기본값 | 쿼리 파라미터 |
|---|---|---|---|
| 총 금액 | (기존) 영수증 전체 금액. 술값 포함 | 10000 | `total` |
| 인원 | (기존) 전체 인원 | 3 | `people` |
| 술값 | 총 금액 중 술에 해당하는 금액 | 0 | `drink` |
| 마신 사람 | 술을 마신 인원 수 | 0 | `drinkers` |

술값이 0이면 지금과 똑같이 동작한다. 기존 링크(`?total=...&people=...`)는 그대로 쓸 수 있다.

### 계산 규칙

1. 공통 금액 = 총 금액 − 술값 → 전체 인원이 나눈다.
2. 술값 → 마신 사람끼리 나눈다.
3. 마신 사람 = 공통 몫 + 술 몫, 안 마신 사람 = 공통 몫.
4. 나누어떨어지지 않으면 #1(PR #4)과 같은 규칙으로 앞사람부터 1원씩 더 낸다. 공통 금액과 술값에 각각 적용한다.
5. 받은 돈 합계는 항상 총 금액과 같다.

### 보이는 것

- 목록에서 마신 사람이 먼저 나오고, 이름 옆에 🍺 표시가 붙는다. 예: `1번 🍺  22,000원`, `4번  12,000원`
- 목록 아래 합계 확인 줄(`받은 돈 합계 / 결제 금액`)은 지금처럼 보인다.

### 오류 메시지 (목록 자리에 표시, 기존 방식과 같음)

| 조건 | 메시지 |
|---|---|
| 술값이 음수이거나 정수가 아님 | `술값은 0 이상의 정수여야 합니다` |
| 술값 > 총 금액 | `술값이 총 금액보다 클 수 없습니다` |
| 마신 사람 > 인원 | `마신 사람이 전체 인원보다 많을 수 없습니다` |
| 술값 > 0 인데 마신 사람 = 0 | `술값을 나눌 사람이 없습니다` |

### 예시 계산

**예시 1 — 나누어떨어지는 경우**

`?total=90000&people=5&drink=30000&drinkers=3`

- 공통 60,000원 ÷ 5명 = 12,000원
- 술 30,000원 ÷ 3명 = 10,000원

| 사람 | 금액 |
|---|---|
| 1번 🍺 | 22,000원 |
| 2번 🍺 | 22,000원 |
| 3번 🍺 | 22,000원 |
| 4번 | 12,000원 |
| 5번 | 12,000원 |

합계 22,000×3 + 12,000×2 = 90,000원 ✅

**예시 2 — 잔돈이 생기는 경우**

`?total=100000&people=4&drink=25000&drinkers=3`

- 공통 75,000원 ÷ 4명 = 18,750원 (나머지 0)
- 술 25,000원 ÷ 3명 = 8,333원, 나머지 1원 → 1번이 1원 더

| 사람 | 금액 |
|---|---|
| 1번 🍺 | 27,084원 |
| 2번 🍺 | 27,083원 |
| 3번 🍺 | 27,083원 |
| 4번 | 18,750원 |

합계 27,084 + 27,083×2 + 18,750 = 100,000원 ✅

## 기술 스펙

### 바뀔 함수

`src/split.js`에 함수를 하나 추가하고, 기존 `splitBill`은 그대로 둔다(PR #4의 나머지 배분 로직을 재사용).

```js
// 술값은 마신 사람끼리, 나머지는 전원이 나눈다. 마신 사람이 배열 앞쪽에 온다.
export function splitWithDrinks({ total, people, drink = 0, drinkers = 0 })
// → [{ amount: number, drinker: boolean }, ...]  (길이 = people)
```

- 내부: `common = splitBill(total - drink, people)`, `drinks = drinkers > 0 ? splitBill(drink, drinkers) : []`
- `i < drinkers`이면 `{ amount: common[i] + drinks[i], drinker: true }`, 아니면 `{ amount: common[i], drinker: false }`
- 위 오류 표의 조건에서 `Error`를 던진다.

`src/app.js`

- `drink`, `drinkers` 입력값과 쿼리 파라미터를 읽는다.
- `splitBill` 대신 `splitWithDrinks`를 호출하고, `drinker`가 참이면 라벨에 ` 🍺`를 붙인다.
- `sum`에는 `amount`만 뽑아서 넘긴다.

`src/index.html`

- `<label>술값 <input id="drink" type="number" min="0" step="1" value="0"></label>`
- `<label>마신 사람 <input id="drinkers" type="number" min="0" step="1" value="0"></label>`

변경 파일은 `src/` 3개(`split.js`, `app.js`, `index.html`). CLAUDE.md의 "바로 수정" 기준(2개 이하)을 넘으므로 구현도 사람 승인 후 진행한다.

## 사람이 정할 것

### 1. 마신 사람을 어떻게 입력받나

- **(추천) 인원 수로 입력** — "마신 사람 3명". 지금 화면이 사람을 `1번, 2번…` 번호로만 다루고 이름 입력이 없으므로, 수만 받는 게 가장 작은 변경이다. 쿼리 파라미터로 공유하기도 쉽다.
- 사람마다 체크박스 — 누가 마셨는지 정확히 표시되지만, 이름이 없는 지금 화면에서는 "몇 번이 누구인지"를 사용자가 따로 기억해야 해서 이점이 작다.

### 2. 술값을 어떻게 입력받나

- **(추천) 총 금액에 포함된 술값을 따로 적는다** — 영수증 총액을 그대로 넣고, 그중 술값만 옮겨 적으면 된다. 결제 금액 확인 줄이 영수증과 그대로 맞는다.
- 음식값과 술값을 각각 입력 — 총액을 사용자가 더해야 하고, 기존 `total` 입력의 의미가 바뀐다.

### 3. 잔돈(나누어떨어지지 않는 금액)은 누가 더 내나

- **(추천) PR #4와 같이 앞사람부터 1원씩** — 규칙이 하나라 설명하기 쉽고, 마신 사람이 앞에 오므로 술값 잔돈은 마신 사람이 낸다.
- 공통 금액의 잔돈을 마신 사람에게 몰기 — "술 마신 사람이 더 낸다"는 취지에는 맞지만 규칙이 둘이 된다.

### 4. 마신 사람을 목록 앞에 모을까

- **(추천) 앞에 모은다** — 구현이 단순하고(인덱스 비교 하나), 🍺 표시로 한눈에 구분된다.
- 번호 순서를 유지하고 사람마다 선택 — 1번 결정에서 체크박스를 고를 때만 의미가 있다.

### 5. 범위 밖으로 둘 것 (확인만)

"안주는 마신 사람만", "특정인이 더 냄"처럼 항목별·사람별 가중치는 이번 스펙에 넣지 않는다. 필요하면 별도 이슈로 받는다.
